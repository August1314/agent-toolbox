# 整包 agent skill 当工具用：anything2explainer 的黑画布解说片产线

> 来源：`tools/anything2explainer/`（Vincentwei1021，PolyForm Noncommercial 1.0.0，
> 入口是 `SKILL.md`，**不可 `toolbox run`**）。
> 本卡片记的是**把它当工具用时撞到的东西**，不是它的使用方法 ——
> 命令原文与产物路径在使用方工程的 `harness-video/content/TOOL_INTERFACE.md`。
> 三轮实测（2026-11-02 ~ 11-03），成片 198.0s / 5941 帧 / 3 章 19 镜。

## 一、结论（可直接用的判断）

1. **质感型解说片的最优复用单位是"整包方法"，不是组件。** 这类 skill 一次性带来
   模板 + 原语 + 光效 + QC 脚本 + 参考片 + 多 agent 派单协议。自己攒组件的观感上限
   取决于我，攒齐它们的成本取决于运气。
2. **复用 = 连它的流程契约与量化判据一起接。** 它的四道用户闸门（时长语言 / 解说词定稿 /
   TTS 偏好 / 前 30 秒样片）与七条 QC 阈值就是它质感结论的来源，跳过闸门等于把工具
   降级成零件。
3. **它的"参考成品"是产物文件，不是可跑工程** —— 基线只能走同构比对（见下 §3）。
4. **它自带的硬约束会反向重塑内容层**，用有出处的事实满足，不要改工具、不要堆修辞。

## 二、什么时候用 / 不用

| 用 | 不用 |
|---|---|
| 中文或英文的**解说片 / 概念片**，黑白画布 + 线稿 + 字幕带 + 章节进度条这套语言可接受 | 需要实拍素材拼贴、AI 生图、非程序化绘制 |
| 要"信息密度高、节奏快、动效多"的观感，且愿意照它的产线走 | 只要一张静态图或 10 秒内的短片（它的阶段 0→8 比片子长） |
| 个人 / 非商用 | **商用**：PolyForm Noncommercial 需作者授权，成片不得商用分发 |

边界与成本：默认 1280×720@30；整片渲染 10–40 分钟；vendor 目录 286MB（其中
`template/node_modules` 263MB —— **装在调用侧，别让它在 vendor 里长出来**）；
Python 侧要 venv（edge-tts / numpy / pillow / scipy）。

## 三、基线：跑不动的标杆怎么验（同构比对三档）

工具箱里的 `examples/rag/` = **23 张成品帧 + 9 个镜头源码目录，没有 `package.json`**。
"渲染参考片再抽帧比对"这条烟测**做不到的**，重跑等于重拍一部片。三档处置：

- **① 同构比对**：`new_project.sh` 出工程 → `npx tsc --noEmit` →
  `scripts/still.sh Overlay 40,120,200,280 <目录> ov`，与样片帧对画面要素。
  **但先确认每一项在空工程里真出得来像素**：这一轮真正比对到的是黑画布 / 幕底（点阵波）/
  白线稿 + 紫重点 / 字体与描边规格四项，**描边字幕带与进度条 + HUD 是派生量，出不来**（见③）。
- **② 指认真闸门**：观感档次由工具自己的确认点 4（`preview.sh 30`）裁决，同构比对不算观感验收。
- **③ 顺延登记**：模板发的是 `TOTAL_FRAMES=300`、`CHAPTER_STARTS=[]`、`SENTENCES=[]`、`SUBS=[]`
  （`common/timeline.ts:2-5`、`common/subs.ts:3`），凡派生自它们的数组在空工程里一律为空 ——
  逐条 grep 出 **七项验不到**：章节卡 `CHAPTER_CARDS`（`Overlay.tsx:59`）、进度条章节标签
  `CHAPTERS`、进度条分隔线 `DIVIDERS`（`ProgressBar.tsx:18/26`）、HUD 小节胶囊（`Overlay.tsx:92`
  的 `SENTENCES.length ? … : []`）、流程轨 `RAILS`（同处）、字幕带 `SUBS`、末段边界 `LAST_TO`。
  全部顺延到 `tts_build.py` 出真实帧号之后复验，索引保持 `verified: false`。
  **教训：①的要素清单与③的验不到清单必须互斥** —— 原先写"对五要素"，却把其中根本画不出来的
  派生项算进了"已比对"，是自己给自己发的假证书。

## 四、坑（每条都可 grep，来自真实返工）

### 环境层

- **可达是「源 × 下载器 × 时段」矩阵，而且矩阵的格子会变。**
  2026-11-03 那晚：`curl` 同 URL 200，pip / uv（rustls）对 `pypi.org/simple` 一律
  `ConnectionReset`（TLS 指纹被 reset）；`github.com` 的 git 端点超时而
  `codeload.github.com` / `api.github.com` 通 → 用 codeload tarball 解包 vendor（无 `.git`）。
  **2026-11-04 复测：`pip download edge-tts==7.3.1` 退出码 0、wheel 38908 字节落盘** ——
  那格的结论翻了。所以：写"某源不可达"必须带日期与客户端，**别把一次绕行做成永久规则**，
  也别在换了一个下载器之后就顺手判"网络没问题"（反模式 16 的两个方向都成立）。
- **真正坏掉的不是 PyPI，是微软的语音 socket**：`edge-tts 7.2.8` 请求
  `wss://speech.platform.bing.com` 返回 **403**、产出 **0 字节**文件；
  同环境下 `7.3.1` 出 14688 字节的 mp3（`ffprobe` 回读 2.448s）。
  判"某个 TTS 引擎挂了"要看到**产物字节数**，不是看到命令退出。
- **代理失效只在会话内覆盖**：`git -c http.proxy= -c https.proxy=`，**不动用户全局配置**。
- **离线 wheel 清单会把人选回坏版本**：`fetch-wheels.sh` 硬编码 `edge-tts 7.2.8`，
  而 7.2.8 请求微软语音 socket 时 **403**（微软改了握手，产物 0 字节），
  PyPI 最新 7.3.1 直接修好。
  → 修一次就回写清单；这类一次性绕行脚本**留在项目里，不进工具箱**。
- **版本事实会过期**：上一轮锁 remotion 4.0.489，本轮工具钉的 **4.0.507 直接装通渲通**。
- **降级候选要按质感闸门判，不按"能跑"判**：piper / kokoro（HuggingFace 不可达）、
  macOS `say -v Tingting`（可跑但音色低于参考片的云希）→ 都被否，
  因为**音色掉档就是质感不达标**，不是功能可用性问题。

### 工具自己的验收器（隐式格式契约）

- `selfcheck.py` 的正则要 `SC\d\d\s+`（id 后**必须有空格**）：19 条压成一行只解析出 **5 条**。
- `re.search` 取**首个**同名短语：镜头表里更早出现的"扫光白名单"字样被先匹配走 →
  读出 **0 条 → 任何扫光都判不出超标**。
- 更绕的：把"无 glitch"的镜头也当成白名单键，等于**要求它们非闪不可**。
  → 修法全在**改自己文档的写法**（分条带空格、无 glitch 的 5 镜移出捕获区、
  把"扫光白名单"改成"扫光镜头"让全局约束 §7 成为全文第一处），不动工具。
- **通则：让校验器打印它解析到的条数，与预期条数核对；0 条 ≠ 全部合格。**

### 校验器与产物对账

- **自推公式的校验会给出假 PASS**：`check-timeline.mjs` 闸 5 自己按理想公式推镜头界，
  它 PASS，而分镜表真正写出来的 `{末句.to+2}` 是坏的 —— 相邻镜头 **16–52 帧空场**、
  16/19 镜"末拍 → 镜末"不足 60 帧。
  → 帧列改成 `{下一段首句.from−9}`；章末两镜单独 `末句 to+38` + `## gap 45`
  让章节卡从 `to+39` 起；**校验脚本改成读渲染出来的 `分镜表.md`**，并新增空档闸
  （≤1 帧相接 或 ≥40 帧整张章节卡，中间值判缺陷）。
- **段末落位的口径**：工具警告只看字幕块自身长度（末块 <45 帧），**不知道镜头尾巴还会延伸**。
  正确口径是"末块结束 → 镜头结束 ≥30 帧"，13 句报警里只有 6 句真不达标。
- **只看 stdout 的断言会放过崩溃**：CLI 抛 Traceback 时前半段输出照样匹配关键词 →
  同时判**退出码与 stderr**。

### 编排与镜头数学

- **片尾压黑吃掉末镜头收尾**（工具 `lessons.md` 里已是**第三次**记录，本轮仍差点踩中）：
  SC19 象征物 draw-on 挂第 2 拍 → 5772+46=5800 才落位，而压黑 5810 起、5840 全黑，
  最后一个动作几乎在暗场里做完。→ 挂**第 1 拍** 5726，落位 5772，压黑前留 38 帧干净可见，
  并去掉与压黑重复的 `exitFade`。
- **`## gap N` 加给下一句，却真的算进上一个镜头的停留** —— 停留预算来自段末留白，不是拖。
  片长比纯语音长 **27%** 是正常值。
- **按整句 / 按段写文案**：一行一句、每句 ≤35 字、一段（2–4 句）= 一个镜头；
  `|` 只切字幕块不影响朗读。
- **定稿后不要改词**：帧号被镜头代码硬编码，改词 = 全体重对位。
- **`GlowBlob` 的 `N` prop 是诱惑型开关**（传了就有呼吸），与"不为凑动作加呼吸"的动效纪律
  直接冲突 → 属于陷阱 API，调用处要写明它对应哪条纪律。
- **`exitOp` 首步淡出会污染 `motion_check` 的 hold 读数** —— 量具与被测对象共用代码时
  存在这类耦合；SC19 的离场因此取 10 帧（协议 N=6–12 区间内，允许）。
- **协议点名的导出必须真的在共用层**：把 90 个导出名跑一遍存在性检查，只缺 `RAIL_CX`，
  而它是 `Overlay.tsx` 的**模块私有**常量（流程轨归覆盖层画）→ **改文档措辞，不导出它**，
  免得诱导跨层依赖。
- **常驻层先验，再验内容层**：`still.sh Overlay …` 20 帧拼 contact sheet，
  一次看完片头卡 / 两张章节卡 / 流程轨四步 / HUD 换词 / 进度条切章 / 压黑 / 署名卡。

### 内容层与事实层

- **内容只写在工具的唯一输入位**（`script/narration.txt`），验收脚本指过去，不留副本。
- **章名 ≤6 字**是进度条槽宽（1280 ÷ 章数）决定的硬规：「马的视角与我们」（7 字）压成
  「马的视角」（4 字），转折留在解说词与 HUD 小节名里。
- **每章 ≥60s** 卡住 55s 的 CH2 → 补的是有出处的工程事实
  （`每一轮开工|先塞给它三百多个 token|那是工具的说明书` ← AWS Bedrock 文档表
  Tool use system prompt token count = **346 token**，Claude 4.5 系列，启用工具、
  `tool_choice=auto`），不是修辞。
- **画面字面量必须有唯一出处白名单**（`research/调研.md` §8），事实层复核这轮改了 **3 处**：
  ① harness 的 c.1300 义项"个人作战装备/盔甲"**同期已含战马护具**，"先盔甲后马具"的先后不成立；
  ② 内省实验的实测口径是"注入概念后约**两成**试验里它能在影响输出前察觉"，
  不是"自述理由两成对得上"；
  ③ "连上一轮都记不全"不成立 —— 多轮历史每轮重传，真实机制是**窗口溢出后从最早的消息截断**。
  两个柏拉图出处要拆开：坟墓＝`sōma sēma` 在**《克拉提洛斯》404c**，
  被贝壳海草糊住的海神格劳科斯在**《理想国》611d–612a**。
- **委派产物的两向误判**：subagent 回报"已写文件"时文件确实没落盘、还给过两个 404 URL；
  稍后它自己完成了 130 行调研稿。→ **总结是意图不是产物**，落盘 / 条数 / 来源自己核；
  但核的时机是**完成通知之后**，别据一次"还没出现"就判它没做。

## 五、拟上游（别写进 vendor）

`reference/lessons.md` 开头写着"新片结束后把新教训追加到这里" —— 那是别人的仓库，
按上游重取即被冲掉。本轮三条想提给上游，**先记在这里**：

1. `selfcheck.py` 的白名单正则应容忍"一行多条"写法，并在输出里打印**解析到的条数**；
2. 章末镜头界公式（`[首句 from−8, 下一句 from−9]`）应由 `render_storyboard.py` 直接产出列，
   而不是让使用方自己推算（推算就会和产物不一致）；
3. `GlowBlob` 的 `N` prop 应在签名注释里写明"传 N 即呼吸，动效纪律禁止"。

上游收下后再删本地副本并注明版本。
