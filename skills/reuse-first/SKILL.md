# 先复用后自建

## 何时启用

**产出型任务**开始时启用。产出型 = 会产出代码、文档、图像、视频、表格、报告、配置或流程。

以下情况**不启用**：纯问答、概念解释、改一个已有文件里的单点 bug、
纯粹闲聊与讨论、纯思考与决策。

不确定时倾向启用。检索的边际成本远低于错误方向上的自建。

---

## 核心原则

### 原则一：搬进来的是工具本身

拿到别人的工作后，**直接调用**，不要读懂后重写一遍。
重写一遍的 token 代价 ≈ 从零实现，而且额外付了理解成本。

正确做法：装进工具箱 → 写一个薄 adapter（只做参数映射和输出约定）→ 调用。

**这不是"复现"。复现是我们要消灭的行为。**

### 原则二：必须先搜，但不强制复用

- 产出型任务**不允许跳过检索直接自建**
- 搜不到合格成果就自建 —— 这是正常结果，**不算失败**

强制复用会引入更糟的东西：脆弱依赖、陌生代码、上游 breaking change。
**检索本身才是成本，复用才是收益。**

### 原则三：检索的单位是环节，不是任务

搜"帮我做一个 X"几乎搜不到可用成品 —— 成品总是针对特定内容的。
但搜"提取 PDF 表格并保留合并单元格样式"、"把音轨对齐到视频帧"，
这些**环节**有大量现成实现，别人已经把边界情况都踩过了。

真实成本几乎总是集中在环节上，不在任务整体上。

## 执行流程

### 第 0 步：查工具箱（成本最低，先做）

```bash
toolbox lookup <能力标签>
```

能力标签用**技术名词**而非自然语言意图。
例如 `pdf table extract`、`subtitle burn`、`audio align`、`vue list page`。

命中 → 直接用，跳到第 5 步。

```bash
toolbox probe        # 不知道有什么可查时，先看本机各 agent 已装能力
```

### 第 1 步：拆任务环节

把任务切成可独立验收的步骤，每步问：**这一步有没有现成实现？**

三个判定信号，命中任一即为**可检索环节**：

| 信号 | 说明 |
|---|---|
| 明确的输入/输出契约 | 能一句话说出输入什么、产出什么 |
| 明确的失败模式 | 容易出错的地方，大概率有人写过防护 |
| 明确的质量标准 | 有客观判据，而不是"看起来不错" |

反例对照：

| 任务片段 | 可检索 | 理由 |
|---|---|---|
| "做一个音乐搜索下载网站"（整体） | 否 | 无稳定接口，内容高度特化 |
| "调用某站搜索接口" | 否 | 无公开稳定 API，无契约 |
| "多站并发聚合与去重" | 是 | 输入输出明确，有质量判据 |
| "PDF 表格提取保留合并单元格" | 是 | 失败模式明确（合并单元格丢失） |

只对**可检索环节**继续。不可检索的环节直接自建，不浪费时间。

### 第 2 步：四源检索，按成本从低到高，命中即止

| 序 | 源 | 查什么 | 命中后动作 |
|---|---|---|---|
| 1 | 本地已装 | `toolbox probe` 输出的各 agent skill 与 MCP | 直接调用，零安装 |
| 2 | 自己过去 | 历史会话、项目代码库、记忆文件 | 抄自己现成的实现 |
| 3 | 开源社区 | GitHub / npm / PyPI / HuggingFace | 下载装入 + adapter |
| 4 | 文章教程 | awesome-list、踩坑记录、best practice | 转成知识条目 |

**前两源命中就不该再往下搜** —— 这是省 token 的主战场。
第 4 源最容易产出"看起来很有道理但没用"的噪音，只在前三源无解时启用。

### 第 3 步：搜索词构造

关键词**必须带技术名词和约束条件**，不能只用自然语言意图描述。
约束条件正是把营销内容筛掉的那部分信息。

```
差:  pdf table extraction tool
好:  github pdfplumber extract_table keep merged cells
```

### 第 4 步：静态筛查（不下载、不运行）

只读 README / manifest / 包元数据，判断五项：

| 维度 | 看什么 | 不合格的处理 |
|---|---|---|
| 许可证 | MIT / Apache / BSD 可用；GPL / AGPL 谨慎；无许可证默认不可商用 | 换候选 |
| 活跃度 | 最近提交时间、issue 响应、是否 archived | 换候选 |
| 依赖 | 依赖树深度、体量、是否需要 GPU / 系统权限 | 超重则换候选 |
| 契合度 | 输入输出契约是否匹配本环节 | 换候选 |
| 体量 | 安装时间与磁盘占用是否值得 | 权衡 |

### 第 5 步：烟测冠军

只对静态筛查后的**最优 1–2 个**候选跑最小烟雾测试：能出正确结果即可。
不跑全量测试套件 —— 那是自己实现时才需要的成本。

**失败即回退**：标记该候选 `broken`、记录失败原因、立刻回退自建。
绝不让"工具坏了"卡住整个任务。失败记录本身有价值，下次不会重复踩。

### 第 6 步：接回任务

按下面的三态决策把结果落定。

---

## 三态决策

每个环节最终落到三态之一：

| 态 | 含义 | 落地 |
|---|---|---|
| **复用** | 装入工具箱，任务中用 adapter 调用 | `tools/<id>/` + index 条目 |
| **借用** | 借鉴流程与结论，不直接调用代码 | `knowledge/<id>.md` |
| **自建** | 检索无解，自己写 | 留在项目里，不进工具箱 |

**「借用」不可省略。** 有些最好的成果不是代码，而是别人已经验证过的流程设计与参数结论
（"动效数据流先跑通再蒸馏"、"先用预跑校准时间戳"这类）。
只判"装"与"写"的二分，会把这整类高价值复用误判成"不可用"。

## 装入工具箱

### 可执行 → 装进 tools/

```
tools/<id>/
├── vendor/       # 别人的代码，原样，一个字不改
├── adapter.sh    # 薄适配：参数映射 + 输出约定
└── README.md     # 来源、许可、入口、限制
```

**vendor 原样，adapter 在外。** 不要为了适配自己的目录结构去改 vendor 里的代码 ——
改了就无法安全升级上游版本。

adapter 只需满足统一调用契约：

```bash
toolbox run <id> --in <输入路径> --out <输出路径> [--opt k=v ...]
```

成功时 stdout 输出结果路径，失败时 stderr 输出人类可读原因，退出码非零。

### 不可执行 → 沉淀进 knowledge/

纯文档类成果（风格指南、排版模板、处理流程、参数调优结论）写成 `knowledge/<id>.md`。
不要把文档伪装成可执行工具塞进 `tools/`。

### 登记索引

在 `index.yaml` 增加条目。`provides` 是**能力标签** —— 检索按标签匹配，不按名字匹配
（名字会变、作者会改名、能力不会）。

```yaml
- id: pdf-table-extract
  name: PDF 表格提取（保留合并单元格）
  kind: executable
  provides: [pdf, table-extract, xlsx-export]
  source:
    type: github
    url: https://github.com/...
    license: MIT
  entry:
    command: ./adapter.sh
    args: ["--in", "{input}", "--out", "{output}"]
  contract:
    input: PDF 文件路径
    output: CSV 或 JSON
    limits: 单文件 < 50MB，扫描件不支持
  cost:
    install_minutes: 2
    smoke_test: "./adapter.sh --selftest"
  verified: true
  status: ok
  added_at: 2026-11-02
```

## 搜索预算（硬上限）

检索必须有上限，否则"先搜一轮"会退化成"先搜三轮"。

- 每环节最多 **4 次**检索调用
- 单任务跨环节合计 **≤ 12 次**
- 触顶即强制做决定：装冠军 / 借用 / 自建 / 放弃优化该环节

超过预算仍可继续，但必须在最终产出中**显式写明"此处未穷尽检索"**。

---

## 反模式（禁止）

1. **复现** — 拿到源码后重新实现一遍，等于白烧 token。搬进来直接调。
2. **过度适配** — 为了适配自己的目录结构去改 vendor 代码。适配写在 adapter 层。
3. **索引污染** — 把只用过一次的一次性东西塞进工具箱。工具箱只收**可复用**的工具。
4. **检索瘾** — 明明本地已有等价能力，还在开源社区里搜三小时。本地命中即止。
5. **知识当代码** — 把纯文档伪装成可执行工具塞进 `tools/`。文档进 `knowledge/`。

---

## 完成时自检

任务收尾时逐条检查：

- [ ] 每个环节是否都做过检索？（不允许"本该复用却自建"）
- [ ] 检索预算是否触顶？触顶处是否已写明"此处未穷尽检索"？
- [ ] 新增的 `executable` 条目，烟测命令是否**实际跑通**过？
- [ ] 失败的工具是否已标记 `broken` 并记录了原因？
- [ ] 新工具是否可被 `toolbox lookup <能力标签>` 命中？

**"本该复用却自建的环节还剩几个"是唯一有意义的指标。**
