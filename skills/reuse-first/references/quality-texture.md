# 质感型任务：标杆复刻

> 功能型任务问"能不能做到"，质感型任务问"好不好看"。
> 同一个复用动作，两类任务的检索目标完全相反：功能型找**零件**，质感型找**成品**。

---

## 一、识别：这是质感型任务吗

命中任一即按质感型走：

- 用户用了「高级」「精致」「有质感」「那种感觉」「像 X 一样」这类描述
- 参考对象是一个**成品**（视频、网站、作品集），而不是一份规格说明
- 交付物要给人看，"看起来专业"本身是验收标准之一
- 同类东西自己做出来"能跑但不好看"
- 有对标物：用户会说"要像那个视频那样"

**质感型任务里，最危险的不是做不出来，是做出来了但平庸。**
平庸不会被报错发现，只会被用户的眼睛发现 —— 而那时候已经烧完了全部预算。

---

## 二、开源边界预检（动手前必做）

**先确认：目标质感是否真的在开源范围内？**

很多 repo 开源的是**引擎**，不是**作品**。常见的不开源部分：

- 作者私有的镜头库 / 组件库（"几十个成片专用镜头"）
- 真实品牌设计系统色值（公开的往往是占位色板）
- 成片素材、字体授权、音效

去看这些地方，作者通常会自己写明：

- `CLAUDE.md` / `AGENTS.md`（最常写"私有沉淀不在本仓"的地方）
- README 的 Roadmap / Not included 段落
- 仓库里是否只有 `components/` 没有 `scenes/` 或 `presets/`

**结论分两种：**

| 情况 | 处置 |
|---|---|
| 质感在开源范围内 | 走标杆复刻四步，目标可以定到"接近原作" |
| 质感**不在**开源范围（只有引擎） | **提前降级预期**。把目标改为"用现有引擎把编排做扎实"，明确告诉用户上限在哪 |

第二件事比第一件更重要。**许诺一个搬不到的东西，比坦白上限更伤信任。**

---

## 三、标杆复刻四步

### 第 1 步：找到最接近目标的成品

不是找"能用的组件"，是找**已经做到那个观感的完整产物**。

优先级：
1. 官方 demo / 示例视频 / 在线预览
2. starter 模板的**默认渲染结果**
3. 同类项目的成品展示

找不到成品、只有零件 → 说明这个目标没有现成标杆，如实说明，转自建。

### 第 2 步：先跑起来，一个字不改

```bash
# clone → 装依赖 → 渲染 / 启动 → 看效果
```

**这一步之前不许读它的实现代码。**

为什么：读了代码会让人产生"我懂了"的错觉，然后跳过去自己重写。
而重写必然丢失原作的积累 —— 那些在代码里看不出来、只在效果里存在的微调
（缓动参数、层级顺序、阴影偏移、帧延迟）。

**先看效果，后看代码。** 顺序反了就等于复现。

跑通的标准是 **L3：看到它自己渲染出来的东西**，不是 README 的截图、
不是别人的演示视频。截图可能是另一版本、另一台机器、甚至另一套素材。

跑起来"不像"时，先排除**环境把质感吃掉了**，再怀疑标杆选错：

| 常见吃掉质感的环境因素 | 查法 |
|---|---|
| headless 无 GL → 光效 / 泛光直接不渲染 | 看有没有 `Failed to acquire WebGL context`；本次需 CLI 传 `--gl=angle` |
| 字体未注册 → 排版整体塌掉 | 检查 `@font-face` 是否真的被 import 链触发 |
| 包版本不一致 → 行为回退 | 上一轮锁 4.0.489，这一轮工具钉的 4.0.507 直接装通渲通 —— **"某版本可用"是会过期的事实**，只当历史证据用，别当本轮前提抄 |
| 静音 / 响度未处理 → 听感差一档 | 见 `screening-and-install.md` 的归一化 |

排除完仍不像 → 回第 1 步换标杆。

**如果标杆根本跑不起来 —— 因为它发的不是工程。** 常见形态：`examples/` 里只有成品帧
（或截图 / PDF）加若干源码片段，没有 `package.json`，重跑等于重拍一部片。
这时按三档处置，缺一档都会让"基线"变成自我安慰：

| 档 | 做什么 | 本轮的实例 |
|---|---|---|
| ① 同构比对 | 用工具**自己的出帧命令**出产物，与样片逐项对"画面要素清单"——**清单里每一项要先确认它在空工程里真出得来像素**（派生自占位数据的项出不来，见 ③） | `still.sh Overlay 40,120,200,280`：五要素里只有**黑画布 / 幕底 / 白线稿+重点色 / 字体与描边规格**出得来；描边字幕带、进度条+HUD 是派生量，空时间轴下为 `[]` |
| ② 指认真闸门 | 写明"像不像样片"这件事由工具的哪一步裁决，别把 ① 当观感验收 | 工具的确认点 4：`preview.sh 30`（前 30 秒样片） |
| ③ 顺延登记 | 本轮**验不到的元素逐条列出**，写明顺延到哪个步骤复验。别凭印象列两三项 —— **把占位数组的派生项全 grep 一遍**（`export const X = []`、`Y.length ? … : []`、`.slice/.map( 空数组`），列出来的是七项不是两项 | 模板发的是 `TOTAL_FRAMES=300 / CHAPTER_STARTS=[] / SENTENCES=[] / SUBS=[]` → 章节卡、进度条章节标签、进度条分隔线、HUD 小节胶囊、流程轨、字幕带、末段边界 `LAST_TO` **七项**全部验不到，顺延到 `tts_build.py` 出真实帧号后复验 |

③ 是关键：宁可写 `verified: false` + 顺延位置，也不要写"整体看起来没问题"。
**基线可以降级，验证不许降级。** 而 ① 的要素清单必须与 ③ 的验不到清单**互斥且互补** ——
一边说"我比对了五要素"、另一边承认其中两要素根本画不出来，等于自欺。

### 第 3 步：逐项拆解差异

在跑通的基础上，**只换一个小内容**（一句文案、一个数据点），看哪里崩、哪里变形。
崩掉的地方就是"编排层"的所在 —— 那就是不能动、只能复用的部分。

拆解维度清单（逐项对齐，不要凭感觉）：

| 维度 | 要问的 |
|---|---|
| 纵深 | 有几个层次？前景/中景/背景分别是什么？有没有遮挡、模糊 |
| 物理缓动 | 位移和缩放用 spring 还是 bezier？参数是多少？有惯性吗 |
| 缓动分派 | 每个位移是"有落点"还是"穿越画面"？前者用弹簧，后者必须线性 |
| 纹理 | 有没有 noise / grain / 渐变？叠加顺序是什么 |
| 连贯 | 多个对象的抖动**是否共用同一个噪声场**？各抖各的是贴纸，共抖才是画 |
| 光效 | 发光、阴影、泛光从哪来？有没有色温变化 |
| 编排 | 镜头怎么走？有没有连续缩放、转场、节奏点 |
| 密度 | 每秒有几个动作在发生？（这是"高级感"最直接的量化指标） |

**密度检查特别有用**：数一下标杆成品每 3 秒里有多少个独立动作在同时进行。
自己做的如果只有 1-2 个，观感平庸就是必然的，跟美术无关，是信息密度不够。

**验收方式：静帧**。每拆一个维度，截一张代表性帧和标杆同位置对比。
读代码看不出"注释说被推开、实际是常量"这种假动作 ——
编排层的差异只能靠像素确认（详见 `screening-and-install.md` 的四级阶梯）。

### 第 4 步：只换内容层，保留编排层与物理层

| 层 | 处置 |
|---|---|
| 内容层（文案、数据、素材） | **换掉** |
| 编排层（镜头、节奏、转场） | **保留**，改了就是重造 |
| 物理层（缓动、纹理、光效、层级） | **保留**，这是质感的载体 |

判断标准：改完之后，**遮住文案，画面观感应该仍是同一个档次。**

换内容层时的三条纪律（第三轮实测）：

1. **内容只写在工具的唯一输入位上**（例：`script/narration.txt`），不在自己目录里另存一份，
   验收脚本指过去。两份文案必然漂移，而且漂移后验收测的是副本、渲染用的是原件。
2. **工具的硬规用有出处的事实满足，不用修辞糊过去。** 章名超长 → 砍字而不是改槽宽；
   某章差 5 秒 → 补一条有来源的工程事实（"每轮先塞给它三百多个 token" ← Bedrock 文档表格
   346 token），既过闸又推进论点。**改工具 = 放弃复用**，堆修辞 = 交付一堆空话。
3. **上画面的每个字面量要有唯一出处白名单**，并且让工具的校验器对账它。
   事实层复核这轮改了 3 处解说词（词源先后不成立 / 内省实验的实测口径 /
   "记不全上一轮"其实是窗口溢出从头截断），也拆开了被混用的两个柏拉图出处
   （坟墓＝《克拉提洛斯》404c，海神格劳科斯＝《理想国》611d–612a）。
   **画面里的数字必须有口径与版本标注**（≈20% 标实验口径，346 token 标"版本相关"），
   核到但不上画面的结论要显式记"核到未用"，否则下一个人会以为没查。

### 保住编排层的六种手法（第二、三轮实测有效）

| 手法 | 做法 | 为什么 |
|---|---|---|
| **走官方扩展点注入** | 需要换缓动曲线时，把 spring 塞进 kit 预留的 `easing` 槽，而不是改它的插值函数 | 一行 vendor 没动，升级 kit 直接替换目录即可；本次换曲线零改源 |
| **拿能力，别拿布局** | 用 kit 的相机推场景，但把卡片层挂在相机**外面** | 卡片留在不动的层才读得出纵深；一起被推走就退化成平面 |
| **不用也留判断记录** | 评估过但决定不接的组件，写明理由与代价 | `CameraMotionBlur`：位移约 1px/帧，代价是 samples 倍重渲染 → 不接。**没有这行记录，下一个人会重新发现并误以为漏了** |
| **连它的量化判据一起复用** | 优先搬工具自带的测量脚本与阈值（静止 ≤3.0s、末拍 hold ≥30 帧、主角 ≥170px、小于 110px 不得持续 >45 帧、每镜 ≤1 处闪烁、全片 ≤2 处扫光、每章 ≥3 次运镜），**数不改**，并且**在成片帧上复测**（`--frames fin_frames`）而不是在预览里测。**但要先把它和自己分镜里声明的规格对表**：工具的"<110px 持续 >45 帧"与本片规格里"主角 ≥170px **或大字 ≥96px**"在 96–110px 这段是冲突的 —— 量具报的中项未必是缺陷。**先定"哪个下限管哪一类元素"，再决定修不修**，别拿工具的红字直接换一次重渲 | 那组数字是原作者质感结论的来源；自己另定标准就退化成主观印象。成片复测才是判据，预览会骗人 |
| **常驻层先验，再验内容层** | 先用工具的出帧命令把画布 / 幕底 / 字幕带 / 进度条 / HUD / 章节卡 / 压黑 单独拼成 contact sheet 看完，再开始建镜头 | 常驻层错了，每个镜头都要返工；而它一次就能验完 |
| **上收只做加法** | 各镜头里的本地副本 helper 要升进共用层时，只补兼容的新导出，**不回写已验收镜头的 import** | v1 之前重写 8 个镜头的收益 < 像素回归风险；真正该沉淀的是"模板本来就该自带这三个 helper" |

**弹簧不是风格，是物理。** "都换成 spring"不是保留质感，是制造新 bug：
穿越画面的行程套上弹簧，对象会在终点自己刹车。

**工具的 API 里有一类"诱惑型开关"。** 例：发光组件的 `N` prop 传了就有呼吸感 ——
但"不为凑动作加呼吸"是动效纪律。接这类 prop 前先在调用处写明它对应哪条纪律，
否则下一轮为了"画面再动一点"就会把它打开。（同一个组件的 `exitOp` 首步淡出
还会污染运动检测的 hold 读数 —— **量具和被测对象共用代码时要小心这层耦合**。）

## 四、质感件识别：不看契约，看增量

功能件的价值在"解决一个契约"，质感件的价值在"提升观感"。
后者的增量**完全不体现在契约里**，所以不能用契合度筛。

以下类型的组件，只要存在就纳入候选，**不参与契合度淘汰**：

| 类型 | 识别信号 | 为什么会被误杀 |
|---|---|---|
| 纵深 / 层次 | 景深、遮挡、前景模糊、分层背景、玻璃拟态 | "我的场景是平面的，用不到 3D" |
| 物理缓动 | `spring`、弹簧参数、惯性、过冲 | "interpolate 也能动" |
| 纹理 / 材质 | noise、grain、纸纹、渐变网格 | "纯色也能看" |
| 光效 | 发光、泛光、体积光、投影 | "加不加都能交付" |
| 编排 / 运镜 | 相机系统、pose 序列、连续缩放 | "我场景固定，不需要运镜" |

**共同的误判逻辑：契约不匹配 → 判为不需要 → 跳过。**
而质感恰恰藏在你以为不需要的东西里。

## 五、失败案例复盘（真实，值得完整读一遍）

**任务**：把一篇散文做成手绘风格的程序化视频。参考了某开源手绘视频引擎（MIT，作者是同领域知名项目作者）。

**结果**：78 秒成片，技术指标全部达标（1080p30、字幕同步、确定性渲染）。
用户评价：**"并没有宣传视频里那么多高级质感动效。"**

**事后量化诊断：**

| 指标 | 实际情况 | 说明 |
|---|---|---|
| 参考引擎组件使用率 | 9 个组件只用 1 个（字幕） | 未用的含景深卡、运镜系统、入场动效库、动态底 |
| 质感件忽略行数 | 1651 行未用 / 205 行使用 | 差的恰好全是质感件 |
| `spring()` 调用 | 项目 **0 次**，参考 14 次 | 全程 bezier → 机械感 |
| 画面纵深 | 单层平面线稿 | 无遮挡、无景深、无光效 |
| 开源边界 | 作者私有镜头库**不在仓库里** | 目标观感根本搬不到 |

**三个根因，按严重度：**

1. **目标不可达** —— 宣传片的质感来自私有镜头库，开源仓库只给了引擎。
   动手前没有做开源边界预检，等于追一个不存在的东西。
2. **按契约筛质感件** —— 运镜系统的契约是"输入 pose 序列输出画面"，
   被判定为"我的场景是静态的，不需要"，于是整个跳过了。而"连续缩放"恰恰需要它，
   最后手写了一遍，效果远不如原版。
3. **读代码抽原语** —— 参考仓库的 demo 从未跑起来，只是读了源码、
   抽出四个"原语"塞进自己工程。这是复现，且丢失了原作在效果层的全部微调。

**如果重来，正确路径：**

1. 先做开源边界预检 → 发现质感在私有库 → **提前告知上限**
2. 找到引擎自带的 demo → **跑通，看到一个真实的观感基线**
3. 在跑通的 demo 上只换文案 → 看哪里崩 → 崩的地方就是要保留的编排层
4. 逐项对齐拆解维度 → 发现 spring 是 0 → 位移全改 spring
5. 发现运镜系统没开 → 接入，而不是手写连续缩放
6. 验收：遮住文案，观感是否还在同一档次

## 六、一句话总结

> 功能型任务缺的是**能力**，质感型任务缺的是**品味**。
> 能力可以通过读文档补上，品味只能通过**复刻成品**继承。
> 拆零件拆不出品味 —— 因为品味在零件之间的接缝里。
