# 筛选、验证与装入细则

## 第一段：静态筛查（不下载、不运行）

只读 README / manifest / 包元数据，判断五项：

| 维度 | 看什么 | 不合格的处理 |
|---|---|---|
| 许可证 | MIT / Apache / BSD 可用；GPL / AGPL 谨慎；无许可证默认不可商用 | 换候选 |
| 活跃度 | 最近提交时间、issue 响应、是否 archived | 换候选 |
| 依赖 | 依赖树深度、体量、是否需要 GPU / 系统权限 | 超重则换候选 |
| 契合度 | 输入输出契约是否匹配本环节 | 换候选 |
| 体量 | 安装时间与磁盘占用是否值得 | 权衡 |

### 第五维的例外：质感件不走契合度淘汰

若任务是**质感型**（见 `quality-texture.md`），下列组件**不参与「契合度」淘汰**：

| 类型 | 识别信号 |
|---|---|
| 纵深 / 层次 | 景深、遮挡、前景模糊、分层背景、玻璃拟态 |
| 物理缓动 | `spring`、弹簧参数、惯性、过冲 |
| 纹理 / 材质 | noise、grain、纸纹、渐变网格 |
| 光效 | 发光、泛光、体积光、投影 |
| 编排 / 运镜 | 相机系统、pose 序列、连续缩放 |

理由：它们的增量不在契约里。按契约筛必然把它们全部误杀。

同时，质感型任务还要读一遍仓库的 `CLAUDE.md` / `AGENTS.md` / README，
确认**质感来源是否真的开源**（详见 `quality-texture.md` 第二节）。

**许可证判定要点**：
- MIT / Apache-2.0 / BSD / ISC —— 可用
- GPL-2.0 / GPL-3.0 —— 传染性，闭源产品慎用
- AGPL-3.0 —— 联网服务也触发开源义务
- 无 LICENSE 文件 —— 默认「保留所有权利」，不可用
- Unlicense / CC0 —— 最宽松

**活跃度判定要点**：
- 最近提交在 12 个月内 → 活跃
- 12–24 个月 → 停滞但可能可用
- 超过 24 个月 → 谨慎，先看 issue 里有没有未修的 bug 报告
- 已 archived → 不选

## 第二段：验证冠军（四级阶梯）

只对静态筛查后的**最优 1–2 个**候选投入验证。验证的标准是
「**从产物本身读出预期的效果**」，不是「跑通全部测试」，也不是「退出码 0」。

### 先做可得性预检（三条，任一不通就别进烟测）

| 预检 | 查法 | 实测到的死法 |
|---|---|---|
| **可达** | **用真正会去下载的那个客户端探**，不是用 curl 探 | `curl` 同一 URL 返回 200，而 pip / uv（rustls）对 `pypi.org/simple` 一律 `ConnectionReset` —— TLS 指纹被 reset；`github.com:443` 的 git 端点超时，而 `codeload.github.com` / `api.github.com` 通 |
| **可装** | 目标 Python/系统版本有没有 wheel；release tag 底下有没有 asset | `sherpa-onnx` 无 Python 3.14 的 wheel；某个 release 有 tag 却没挂模型文件 |
| **不静默出错** | 跑一条最刁的样本，检查**丢了什么** | `matcha-icefall-zh` 退出码 0、时长合理，日志里 `OOV word skipped: 'AI'` —— 拉丁词被悄悄丢掉 |

**可达是「源 × 下载器 × 时段」的矩阵，不是域名属性。** 一个源通不代表换客户端还通，
反之亦然；**而且格子会变**：某晚 `pip` 对 `pypi.org/simple` 一律 `ConnectionReset` 而 `curl` 200，
次日复测同一条 `pip download` 退出码 0、wheel 正常落盘。所以每次都要现测，
**别把上一次的绕行当成永久规则写进契约**，也别据今天的成功宣布"网络没问题"。
落地做法：拿工具声明的安装命令原样跑一次（`pip install <x>` / `npm install` /
`git clone`），别用"我以为等价"的探法替它结论。

三条实测过的绕行，按"改调用侧、不改全局配置、不进工具箱"处置：
git 端点不通而 tarball 端点通 → `codeload` 拉 tarball 解包 vendor（内容与 clone 等价，无 `.git`）；
全局代理失效 → 本会话 `git -c http.proxy= -c https.proxy=` 覆盖，**不动用户全局配置**；
pip 被 TLS 指纹拦 → `curl` 拉 wheel 到项目内，`pip install --no-index --find-links` 离线装。

第三条最容易漏：工具不报错不代表它对。烟测断言写成"产物里应当含有 X"，
而不是"产物文件非空"。

### 四级阶梯与下限

| 级 | 断言 | 能骗过它的东西 |
|---|---|---|
| L1 接线 | import 成功、代码里有调用 | 注释写"弹簧推开"，代码里是常量 |
| L2 调用被接受 | 参数被认、退出码 0、产物非空 | 静音没剪，字幕比人声早 |
| L3 产物里有效果 | 从**最终产物**回读预期物理量 | —— 这是可用性的下限 |
| L4 本任务的刁样本 | 用最可能出错的输入做 L3 | —— 质感型 / 时序类到此 |

**影响交付物的环节下限 L3；质感型与"时序 / 对齐"类环节下限 L4。**
只做到 L1、L2 时，索引里必须写 `verified: false`，不能写 `true`。

**标杆跑不动时，基线降级但别把验证降级。** 别人发的"参考成品"有时只是产物
（帧 / 图 / 文档），不是可跑工程 —— 例：某解说片工具的 `examples/rag/` 里是 23 张
成品帧 + 9 个镜头源码目录，**没有 `package.json`**，重跑等于重拍一部片。
此时按三档处置，缺一不可：

1. 把基线改成**结构同构比对**：用工具自己的产物命令（如 `still.sh Overlay <帧>`）出帧，
   与样片帧逐项对"画面要素清单"（画布 / 幕底 / 线稿+重点色 / 字幕带 / 进度条 / HUD）；
2. 指出**真正的质量闸门在工具的哪一步**（例：工具的四道用户闸门里的"前 30 秒样片"），
   别把同构比对冒充成观感验收；
3. 本轮因输入为空而**无法验证的元素逐条列出并写明顺延到哪一步**（例：占位 timeline 的
   `CHAPTER_STARTS=[]`、`SUBS=[]` → 章节卡与字幕条顺延到有真实帧号之后复验）。
   写 `verified: false` + 顺延位置，不写"大致没问题"。

### L3/L4 的取法：回读产物，不回读日志

- 视频 → 从成片 `ffmpeg` 抽帧（不是重新渲染），逐帧扫描黑屏 / 溢出 / 亮度
- 音画对齐 → 从渲染好的 MP4 里解出 PCM，量每句 onset 偏移
  （本次实测 +63…+89ms 由此暴露；`build-timeline` 的日志一切正常）
- 编排层改动 → **静帧验收**：截代表性帧看像素。注释与像素不一致，就是没接上
- 确定性 → 同帧渲两次 `cmp`；文档类 → 关键结论能追溯到来源
- 时长 / 尺寸 / 帧数 → 用 `ffprobe` 实测，不用代码里算的

**验收脚本必须读真正产物，不许自己重推公式。** 实测到的事故：自建的 `check-timeline`
里有个闸"自己按理想公式推镜头界"，它 PASS，而分镜表里真正写出来的那一列是坏的 ——
相邻镜头之间 16–52 帧空场、16/19 镜停留不足。
**重推公式的校验只证明"你和你的错误理解一致"，对不上产物就等于没查。**
落地判据：脚本里每一条断言的输入，要么是被测产物文件本身（读出来解析），
要么是从产物实测的物理量；出现"按规范我应该得到 X"这种推算，就在冒充。

同样地，**只看 stdout 的文本断言会放过崩溃** —— 程序抛 Traceback 时前半段输出照样能
匹配上关键词。校验命令的同时判退出码与 stderr（我这次写的测试就因为只 grep stdout
而给了一个假 PASS）。

**崩溃还会从"反向用例"和"计数器"两个后门溜进来**（实测：子代理对我的验收脚本做变异测试 ——
把 `die()` 改成"打印完拒绝文本再 raise TypeError" —— 旧脚本仍报"全部通过 rc=0"）：

- 要求"退出码非零 + 含拒绝文本"的用例，若写 `$(cmd 2>&1)` 合并两条流，
  **崩溃同时满足这两条**。改成：stderr 收进单独变量，判 ① 退出码非零
  ② 拒绝文本出现在 stdout 或 stderr **任一处**（`die()` 本来就往 stderr 打，
  要求它在 stdout 会出现"修好了反而判失败"的第二次坑）③ 两条流都没有 `Traceback`。
- 测试自己打印的 `检查了 N 次` 必须带下限断言（`N>=3` 之类），
  否则 fixture 没建起来、一条用例没跑，它照样打"全部通过"。
- **通则：任何验收脚本写完，先做一个"输出正确文本然后崩溃"的变异体，看它是否变红。**
  不变红的测试不是测试，是装饰。

### 感知比较前先归一化干扰量

比"哪个更好看 / 更好听"之前，先把不可比的因素抹平：
响度（`loudnorm` 到同一 LUFS，并看 True Peak / LRA）、画幅与 DPI、
时长、取样位置、字号。
**未归一化的偏好不能进索引** —— 那测的是增益差，不是质感差。

烟测命令与它达到的层级一起写在索引里：`cost.smoke_test` + `verified` / `verified_at`。
装完必须**实际执行一次**。

## 四态决策

| 态 | 何时用 | 落地 |
|---|---|---|
| **复用** | 契约明确契合，可直接调用 | `tools/<id>/` + index 条目 |
| **借用** | 只有流程/结论有价值，无代码可调 | `knowledge/<id>.md` |
| **标杆复刻** | 需求是质感 / 风格 / "要有那种感觉" | 先跑通成品，再只换内容层 |
| **自建** | 检索无解，自己写 | 留在项目里，不进 toolbox |

**「借用」不可省略。** 有些最好的成果不是代码，而是别人已验证过的流程设计与参数结论
（"动效数据流先跑通再蒸馏"、"先用预跑校准时间戳"这类）。
只判"装"与"写"的二分，会把这整类高价值复用误判成不可用。

**「标杆复刻」不可省略。** 它与「复用」的区别：

| | 复用 | 标杆复刻 |
|---|---|---|
| 对象 | 零件（组件、库、脚本） | 成品（demo、示例、模板的默认渲染） |
| 顺序 | 拿回来 → 自己装配 | 先跑通 → 再换内容 |
| 保留什么 | 功能 | 编排层 + 物理层 |
| 适用 | 功能型任务 | 质感型任务 |

质感型任务用「复用」的做法去做，会得到"零件都用了但观感还是不对"的结果
—— 因为零件之间的接缝才是品味所在。

完整流程（四步纪律、拆解维度、密度检查）→ `quality-texture.md`

## 装入：可执行工具

```
tools/<id>/
├── vendor/       # 别人的代码，原样，一个字不改
├── adapter.sh    # 薄适配：参数映射 + 输出约定
└── README.md     # 来源、许可、入口、限制
```

**vendor 原样，adapter 在外。** 改 vendor 就无法安全升级上游版本。

统一的是**登记与调用出口**，不是参数名。真实环节的输入不一定是文件
（一段旁白文本、一个项目目录、一组 pose），强行全局统一 `--in/--out`
只会让 adapter 编一套假参数 —— 索引与实现就此分家。

每个 adapter 必须做到四条：

```bash
# 1. 参数形状写进索引 entry.usage —— lookup 原样转告，这是唯一的调用契约
toolbox run <id> <按 entry.usage 拼出的参数>
toolbox run <id> -- <任意透传参数>          # 参数不在 CLI 已知集合里时

# 2. 支持 --selftest：查前置 + 实跑一条最小样本（不能只看文件是否存在）
# 3. 有前置时支持 --setup，条目 status 保持 needs_setup 直到烟测过
# 4. 成功：stdout 输出产物路径或 JSON；失败：stderr 给人话 + 非零退出码
```

**adapter 里不要写业务逻辑。** 那是复现的开始。
adapter 只做：参数映射、输出规范化、错误信息翻译。

**依赖装在调用侧，不装在 vendor 里。** 在 `tools/<id>/vendor/` 或工具模板目录里跑
`npm install`，会把 263MB 的 `node_modules` 长进"vendor 唯一副本"里 ——
下次重装 / 换机 / 发布时它的状态就说不清了。工程副本由调用侧项目持有，vendor 保持解包时的样子。

**钉版本的清单属于工具契约的一部分。** 一次性环境修复脚本（拉 wheel 的清单、锁死的依赖版本）
如果被登记进工具箱，它锁的每个版本都是承诺。实测事故：清单里硬编码 `edge-tts 7.2.8`，
而 7.2.8 请求微软语音 socket 时 403、**产出 0 字节的"成功"文件**（微软改了握手），
PyPI 最新 7.3.1 直接修好 ——
脚本于是成了"每次换机都把人选回坏版本"的机器。修好一次就回写清单，
并在条目 `limits` 里写"版本清单以 `source.last_commit` 时点为准"。

**别把坑写进别人的仓库。** 有些工具自带 `lessons.md` 且开头写着"新片结束把新教训追加到这里"。
直接改它 = 改 vendor：下次按上游重取就被冲掉，而你的工具箱看起来"有这条经验"其实没有。
正确落点：写进我们自己的 `knowledge/<id>.md`（可被 `toolbox lookup` 命中），
另列一份"拟上游"清单准备发 issue / PR。上游真收了，再删本地副本并注明版本。

## 装入：不可执行成果

纯文档类成果（风格指南、排版模板、处理流程、参数调优结论）写成 `knowledge/<id>.md`。

`knowledge/<id>.md` 应包含：
- 结论是什么（不是原文摘抄）
- 什么情况下适用、什么情况下不适用
- 边界条件（成本、副作用）

**整包 agent skill 是第三种形态**：它既不是能 `toolbox run` 的 adapter，也不是一篇知识，
而是别人的一整套方法 + 模板 + QC。登记规则：

- 入口填它自己的方法文件（`entry.command: SKILL.md`），`entry.usage` 写"按其中的方法调用"
  的散文 —— CLI 会把它打在 `用法:` 而不是 `调用:`，因为**拼出 `toolbox run <id> <散文>`
  是一条抄进终端就跑不动的假命令**（这次真发生过）；
- 用它等于**连它的流程契约一起接**：它自己的用户闸门、确认点、preflight 都在契约里，
  不能只拿代码不拿闸门；
- 接口命令**逐条抄进使用方工程的 `TOOL_INTERFACE.md`**（命令原文 + 参数 + 产物路径），
  工具箱里只留指针，不复制它的镜头实现；
- `source.license` 必填且 `lookup` 会显式打出来 —— 非商用 / 需署名这类约束要在调用现场看得见，
  而不是埋在索引字段里。

## 登记索引

在 `index.yaml` 增加条目。`provides` 是**能力标签** —— 检索按标签匹配，不按名字匹配
（名字会变、作者会改名、能力不会）。

```yaml
- id: pdf-table-extract
  name: PDF 表格提取（保留合并单元格）
  kind: executable
  provides: [pdf, table-extract, csv-export]
  source:
    type: github
    url: https://github.com/...
    license: MIT
  entry:
    command: ./adapter.sh
    args: []
    usage: "--in <pdf 路径> --out <csv 路径>"   # 真实参数形状；lookup 会原样打印
    setup: ""                                   # 有前置才填，如 "--setup"
  contract:
    input: PDF 文件路径
    output: CSV 文件路径
    limits: 单文件 < 50MB，扫描件不支持
  cost:
    install_minutes: 2
    smoke_test: "./adapter.sh --selftest"
  verified: true
  verified_at: 2026-11-02
  status: ok
  added_at: 2026-11-02
```

**`status` 四态**（写错会直接误导下一个使用者）：

| status | 含义 | 谁该用 |
|---|---|---|
| `ok` | 现在就能跑 | 烟测当场过 |
| `needs_setup` | 代码在位，前置未就绪（venv / 模型 / 外部服务） | 搬来但没装依赖 —— **这才是诚实的默认值** |
| `unavailable` | 来源不可达 / 装不上，暂时性，写明恢复条件 | 上游域名不通、没有对应 wheel |
| `broken` | 实测跑不通 | `toolbox run` 会直接拒绝 |

**`verified: true` 的准确含义**：登记当时 `cost.smoke_test` 真跑通过，
且验证到达的层级不低于 L3。它**不是**"这台机器现在能跑" ——
换 venv、换系统版本、换网络环境都可能失效，所以要配 `verified_at`。
只做到 L1 / L2 的条目必须写 `verified: false`。

**`cost.smoke_test` 必须写"真做得到、并且真做过"的动作。** 它下一步会被别的 agent
原样执行。实测事故：条目写"渲染 examples/rag 参考片并抽帧比对基线"，
而那个目录里根本没有 `package.json`，跑不了 —— 照它执行的人只会浪费一轮预算，
或者更糟：假装跑完然后把 `verified` 写成 true。
**烟测描述被证伪时立刻改写**，改成实际执行的那个动作。改写完还要再看一眼新动作**自己**
有没有过度声称 —— 这次第一轮改成了"新工程出覆盖层帧，与样片帧对五要素"，看着已经诚实了，
其实其中"描边字幕带 / 进度条 + HUD"在空工程里是占位数组的派生量，**根本画不出来**：
修正后的描述仍然把验不到的项算成了比对过的。判据：把烟测里每个被"对过"的元素，
拿去问一句"它在没有真实数据的工程里出得出像素吗"，出不来的移到"验不到项"里。
并把证伪过程（两轮都记）留在 `knowledge/` 里。

`source.type` 取值：`github` / `npm` / `pypi` / `hf` / `local-skill` / `own-history`。

## 失败即回退

按失败的性质分档标记，不要一律写 `broken`：

| 现象 | 标记 | `broken_reason` 写什么 |
|---|---|---|
| 装上了但跑不通 / 结果错 | `status: broken` | 报错原文 + 判据（下次不必重试） |
| 依赖装不上、域名不可达、没有对应 wheel | `status: unavailable` | 死在哪一步 + **恢复条件**（换 Python 版本 / 换镜像源 / 等上游挂 asset） |
| 客户端层面被拦（TLS 指纹、代理、git 端点被 reset）而换条通道就通 | 不降级，绕行后照常 `ok` | 在 `limits` 写明"本机需 `--no-index` 离线装 / 需 `codeload` tarball"，绕行脚本留在**项目里**不进工具箱 |
| 只是本机没建 venv | `status: needs_setup` | 不算失败，填 `entry.setup` |
| 跑通但静默丢内容（L4 才抓到的那种） | `status: broken` | 写明"退出码 0 但丢了 X"，这类最危险 |
| 工具自带的验收器**解析不到我的输入** | 不是工具的失败，是使用姿势 | 记进 `knowledge/`：它的正则/格式契约是什么、我怎么发现自己被静默跳过了 |

标记完**立刻回退自建**，绝不让"工具坏了"卡住整个任务。
失败记录本身有价值 —— 下次不会重复踩同一个坑，也不会重复投入验证预算。

## 发布工具箱时发什么

工具箱仓库一旦公开，**只发"使用者需要的东西"，不发"作者的过程记录"**：

| 发 | 不发（留本机，进 .gitignore） |
|---|---|
| 工具本体（`tools/` 含 vendor）、索引、skill 与 references、README | 设计与决策记录、试错日志、执行计划（`docs/plans/`） |
| 已验证的坑清单（`knowledge/`） | 指向其它本地项目 / 私人路径的引用 |

判据很简单：**clone 的人会不会用到它**。过程记录对作者有意义（复盘、找回当初为什么这么决定），
对使用者是噪音，而且里面常夹着第三个项目的上下文。
README 里相应地不留这类链接 —— 留着就是一个会指向 404 的门面。

## 项目级叠加

项目可自带 `.workbuddy/toolbox/` 或 `.agent-toolbox/`，其中 `index.yaml` 与 `tools/`
与全局同构。

查找时**项目级优先**：项目里若有同 `id` 条目，直接遮蔽全局条目，
避免在项目特定语境下误用通用版。

## 反模式（禁止）

编号与 `SKILL.md` 的反模式一致，这里是展开说明。**改一处要改两处** ——
两边编号不一致时，以本文件为准并回改 SKILL.md。

1. **复现** — 拿到源码后重新实现一遍，等于白烧 token。搬进来直接调。
   **变体：读代码抽原语** — 把参考仓库的 demo 读完，抽出几个"原语"塞进自己工程。
   这是复现，只是换了名字，且丢失了原作的微调。
2. **过度适配** — 为了适配自己的目录结构去改 vendor 里的代码。适配写在 adapter 层。
3. **索引污染** — 把只用过一次的一次性东西塞进工具箱。工具箱只收**可复用**的工具；
   一次性产出留在项目里。
4. **检索瘾** — 明明本地已有等价能力，还在开源社区里搜三小时。本地命中即止。
5. **知识当代码** — 把纯文档伪装成可执行工具塞进 `tools/`。文档进 `knowledge/`。
6. **按契约筛质感** — 用"输入输出是否匹配"去淘汰质感件。档次、层次、物理缓动
   都不在契约里，这样筛必然把好东西全筛掉。
7. **拿零件当成品** — 质感型任务里收了几个组件就以为复刻完成。
   组件的正确用法是"在原成品里看它怎么被用"，不是单独拎出来用。
8. **跳过开源边界预检** — 追一个根本不在开源范围里的观感。
   很多 repo 开源引擎、不开源作品，动手前必须确认。
9. **把接线当验证** — grep 到 import、退出码 0、产物非空就登记 `verified: true`。
   这只到 L2。真实事故：配音引擎每句自带静音，时间轴按句起点排，
   成片里字幕比人声早几十到上百毫秒，而**中间每一层的日志都显示成功**。
10. **用注释冒充实现** — 文档写"已沉淀进工具箱 / 已用弹簧推开画面"，
    工具箱 grep 不到那条坑，代码里那个变量是常量。
    任何"已完成"的声明都要能被 grep 或像素复核；对不上就是没做。
11. **拿别人的偏好当自己的结论** — 未归一化响度 / 尺寸 / 时长就 A/B，
    然后把"响的那个更好"写进索引。测的是增益，不是质感。
12. **编造调用契约** — 索引里不写 `entry.usage`，凭记忆或凭别的工具的样式拼参数。
    CLI 宁可回答"未声明"，也不替你猜；猜出来的提示会被直接照做。
    **变体：把散文拼成命令** — 条目入口是 `SKILL.md`（不可执行），CLI 仍打出
    `toolbox run <id> <一句说明>`，看着像命令、抄进终端必挂。
    判"能不能 run"要认**入口文件本身**（存在 + 可执行位），不能认 `kind` 的名字。
13. **自推公式的校验器** — 验收脚本按规范自己推算"预期值应当是多少"，而不是读真正产物。
    真实事故：`check-timeline` 的一个闸自己推镜头界，它 PASS，分镜表里真写出来的帧界
    是坏的（相邻镜头 16–52 帧空场、16/19 镜停留不足）。
    **重推公式的校验只证明"你和你的错误理解一致"。**
    同类：只看 stdout 文本、不判退出码与 stderr 的断言 —— 会给出假 PASS。
14. **把坑清单当防护** — 借来别人的 `lessons.md` 读一遍就开工。
    "片尾压黑吃掉末镜头收尾"在工具自己的教训里是**第三次**记录，本轮仍差点踩中，
    拦住它的是派单前手算帧界，不是那句提醒。**没转成一条可跑断言的坑，等于没借到。**
15. **回写别人的仓库** — 把本轮新坑直接写进 vendor 里的 `lessons.md`。
    按上游重取即被冲掉，而工具箱看起来"有这条经验"其实没有。写自己的 `knowledge/`，
    想贡献就走 issue / PR。
16. **拿一个客户端的可达性替所有客户端表态** — `curl` 通就判"源可达"，
    然后 pip / uv / git 各自撞墙（TLS 指纹被 reset、代理失效）。
    可达是「源 × 下载器 × 时段」的矩阵，用工具声明的那条安装命令原样验一次；
    某晚 pip 全挂、次日同一条命令退出码 0 —— 两个方向都不要替全部格子表态。
17. **把"已经修正过"当成"已经核实过"** — 条目被证伪、改写完新描述就不再核它。
    本轮实例：烟测从"渲染 examples/rag 参考片"改成"与样片帧对五要素"，听着已经诚实，
    但其中描边字幕带 / 进度条 + HUD 是占位时间轴（`SENTENCES=[]`、`CHAPTER_STARTS=[]`）
    的派生量，空工程里出不来。**修正后的句子仍然发假证书。**
    判据：改写完把新句里每个"已对过"的元素再问一遍 —— 它在没有真实数据的工程里出得出像素吗？
