# 环节识别细则

## 判定信号（三选一即可）

一个步骤只要命中下列任一信号，就是**可检索环节**，值得花检索预算：

| 信号 | 说明 | 例子 |
|---|---|---|
| 明确的输入/输出契约 | 能一句话说出输入什么、产出什么 | "输入 Excel，输出带透视的 CSV" |
| 明确的失败模式 | 容易出错的地方，大概率有人写过防护 | "合并单元格丢失"、"编码乱码" |
| 明确的质量标准 | 有客观判据，不是"看起来不错" | "生成的表格能被 openpyxl 打开" |

**三个都不命中 → 不可检索，直接自建，不浪费检索预算。**

## 典型判定对照

| 任务片段 | 可检索 | 理由 |
|---|---|---|
| "做一个音乐搜索下载网站"（整体） | 否 | 无稳定接口，内容高度特化 |
| "调用某站搜索接口" | 否 | 无公开稳定 API，无契约 |
| "多站并发聚合与去重" | 是 | 输入输出明确，有质量判据 |
| "Vue 前端列表页" | 是 | 大量现成模板 |
| "PDF 表格提取保留合并单元格" | 是 | 失败模式明确 |
| "给视频加动态字幕" | 是 | 输入输出明确，失败模式明确 |
| "把音轨对齐到视频帧" | 是 | 有客观判据（时间戳误差 < 1 帧） |
| "这一段的文案润色" | 否 | 无客观判据，且需求高度特化 |

## 拆解粒度

**拆到"能独立验收"为止。** 一个环节的验收标准应当是：能说清"做完了怎么判断做对了"。

- 太粗：「实现数据管道」→ 不可验收，不可检索
- 合适：「从 API 拉取分页数据并合并去重」→ 可验收，可检索
- 太细：「写一行 fetch 请求」→ 虽然可检索，但收益低于检索成本

**经验阈值**：单环节的检索预期收益应超过 4 次检索调用的成本。
一个环节如果拆出来只有一两行代码，不值得单独检索。

## 识别顺序

按任务执行顺序扫一遍全部步骤，标出所有可检索环节，**再决定检索顺序**。

不要边做边搜 —— 那样会导致前面环节的发现影响后面环节的判断，产生路径依赖。
先通盘扫描，再按「成本从低到高」排检索队列。
